# 旅行癞疙宝｜前期设计方案 V0.1

日期：2026-09-10。性质：当前工作基线，供后续设计与开发执行。用户已明确将见闻卡增加到 9 张，按三地各三张分配；其他方案尚未逐项验收。数值均为待试玩的初值，文化事实与虚构玩法分开标记。

## 1. 产品定位与基调

执行状态补记：完整 P0 功能和 30 个正式素材已制作，正在整合与交付复检。本文保留最初设计假设；实际结果以 `HANDOF.MD` 和完整首版验收记录为准。开局补一份成熟收成，便于初次体验院坝；其余范围不扩张。

一句话：给住在四川林盘院角的癞疙宝收拾一包吃的，看它慢悠悠出门，再等一封带着乡土气的来信。

- 类型：单人、轻交互、离线推进的放置旅行网页游戏。
- 玩家关系：一起生活、替它留灯的人；准备与关心是玩家的权利，出门后的经历由角色自己发生。
- 目标体验：安逸、有牵挂、偶尔会心一笑。情绪顺序是“在家安心 → 准备期待 → 缺席惦记 → 来信惊喜 → 回家踏实”。
- 目标用户假设：喜欢轻陪伴与收集、愿意每天短暂回来看看的人；不要求懂四川话。
- 日常单次操作目标 1–3 分钟，适合隔半天回来看看；不设连续登录要求。
- 世界：受成都平原乡村启发的微缩动物生活世界，日常器物保留生活痕迹，时代不特指。主角憨、稳、略犟，表达克制。
- 四川范围：首版只取成都平原及周边的林盘、茶馆、竹乡与河街；其他四川地域文化留到独立内容包。

参照《旅行青蛙》官方介绍中的“收集—购买—准备—自行出发—照片/土产”结构 [S1]。本作重点增加“地方物件影响旅途、见闻在家中留下痕迹”，美术使用原创角色、场景、图标和文字。

### 工作范围与取舍

| 层级 | 范围 | 完成界限 |

P0 是内容有限的可玩样片，不承诺长期运营。收满九张卡后可继续重复旅行，展示“这一册收齐了”，不通过稀有度和长等待延长内容寿命。

### 防止偏离的四条标准

1. 新功能必须增强“关心主角、期待旅行、理解地方生活”中的至少一项。
2. 每次只要求玩家做一个轻选择；不引入数值养成和最优配装压力。
3. 离线没有额外损耗，已准备旅程仍正常消耗一份吃食；到期内容自动落入存档，已有收藏不丢失。
4. 任何四川元素都说明“在哪里、怎么被使用、留下什么故事”。只加地名或装饰不算完成地方化。

## 2. 核心玩法

循环：院坝收成换盘缠 → 小铺补给 → 放入吃食与可选用具 → 点“收拾好了” → 自行出门 → 来信入册 → 回家带来纪念物 → 为下一次准备。

### 玩家能做什么

- 能选择：本次吃食、一个可选用具、何时准备、是否看信/翻册、购买与收成。
- 不能指定：目的地、旅途事件、立即返家。物品提示“更容易遇见什么”，保留偶然性。
- 点击主角只触发看一眼或短状态文字；不增加资源、不改变旅程结果。
- 在家无需照料，不设饥饿、健康、好感衰减。没准备时安心待在家。

### 状态与边界

| 状态 | 条件/展示 | 可操作与转移 |
|---|---|---|
| `home` 在家 | 发呆、吃东西、打瞌睡；可看到已归来的角色 | 打开行囊，确认后进入 `packed` |
| `packed` 已备妥 | 布包打好结；显示“包包收好了，等它出门” | 正常 2–5 分钟后自动离家；出发前可改包或取消并释放预留物品 |
| `traveling` 旅行中 | 原来坐的位置空着，包不在；屋内依然可观察 | 看见闻、收成、购买；本次包只读，暂不准备下次；到时自动回 `home` |

归来是事件，`hasUnreadReturn` 表示尚未看归来内容，不作为阻挡角色活动的第四个状态。纪念物与盘缠自动入账，看信、关闭弹层、刷新都不重复结算。

确认行囊时预留库存；真正离家时扣除一份吃食，用具永久保留。取消不损耗；不允许把同一份吃食重复预留。所有旅行结果在出发时抽定并存档，刷新不重新抽取。

### 时间设计

- 首趟教学：确认后 15 秒离家，旅行 90 秒，中途第 45 秒来信；固定到道明竹乡、固定第一张卡与小竹垫。首次 3 分钟内看见完整循环，提示“这回先在附近转转”。
- 正常：等候出发 2–5 分钟，旅行 2–4 小时，过半来一张见闻卡；目的地不改变这档时间。时间是游戏节奏，不表示真实交通距离。
- 默认展示“在家 / 收拾好了 / 出门转悠 / 有新来信”，旅行详情可看宽泛预计归来区间，不显示秒级倒计时。
- 页面关闭后按时间戳补算；长时间离线最多完成已经准备的一次旅行，不连锁出发、不重复消耗。
- 原型评审提供独立测试入口，把一次正常旅程压到 60 秒；正式玩法界面不放时间加速按钮。

### 选择怎样影响旅程

三地起始权重均为 1；叶儿粑让竹乡权重 +1，锅盔让茶馆权重 +1；小竹筒让竹乡权重 +1，油纸伞让河街权重 +1。归一化后抽取，仅改变概率；基础饭也能到所有地方并收齐全部内容。这些关联是虚构玩法，食物不被宣称为某站独有。

例：叶儿粑 + 油纸伞时，竹乡/茶馆/河街权重为 2/1/2。给玩家的说明是“带上叶儿粑，更想往竹林边走；带伞，河边走走也踏实”。

防重复：连续两趟去同一地时，下一趟临时排除该地。每站优先给未见的卡片与未得的纪念物；站内收齐后允许重复，卡片记录最近获得时间与次数，重复纪念物只累加数量。全册不设强制收齐期限。

每站有 3 张见闻卡、2 种纪念物，两类内容分别从本站池中选取，不一一绑定。每趟仍为 1 卡 + 1 纪念物；第三次去同站可获得新卡和重复纪念物。手账总数从配置计算，当前为 9，不把收藏完成条件写死为 6。

### 轻量经济（试玩初值）

| 项目 | 数值 | 目的 |
|---|---|---|
| 唯一货币“盘缠” | 初始 24；界面用“文”作虚构记账单位 | 降低理解成本 |
| 院坝收成 | 每 4 小时积累一份，每份换 12 文，最多存 3 份 | 鼓励偶尔回来；满了不腐坏 |
| 家常饭 `food_home_meal` | 0 文，随时可装一份 | 资源耗尽仍能旅行 |
| 叶儿粑 `food_yeerba` / 锅盔 `food_guokui` | 各 8 文/份，出发消耗 | 提供横向偏好，不提高奖励档次 |
| 小竹筒 `gear_bamboo_flask` / 油纸伞 `gear_oilpaper_umbrella` | 各 24 文，一次购买永久复用 | 逐步获得第二个选择维度 |
| 归来 | 每趟 8 文 + 1 件纪念物；旅中已有 1 张卡 | 常规吃食能够自循环 |

院坝用三处簸箕收成表现，点击一次收取所有成熟份额，自动换盘缠；这是资源的抽象交换，不展开播种、加工、售卖链。免费饭路线与购买路线都不会出现无法再次出门的情况。

## 3. 交互与信息结构

移动端竖屏优先，桌面居中显示同一游戏画布；场景固定，不用拖拽镜头。常驻结构：顶部盘缠/设置、中央场景、底部“屋里 / 院坝 / 行囊 / 手账”。小铺从院坝的货架进入。

| 入口 | 玩家目标 | 状态与反馈 |
|---|---|---|
| 屋里 | 看它在做什么 | 点角色得到一条短句；离家后保留空位和短笺 |
| 院坝 | 收成、去小铺、看信 | 簸箕成熟用外形变化；信夹有未读纸角；打开后未读标记消失 |
| 行囊 | 准备一份吃食 + 一个可选用具 | 点击槽位再选物品；主按钮“收拾好了”；无吃食时就地提示并提供免费饭 |
| 小铺 | 买补给 | 展示价格、库存、用途；点击“买一份”；用具显示“已拥有”；盘缠不足给出“先装家常饭”入口 |
| 手账 | 看见闻/纪念物/旅程记录 | 三个页签；空格仅显示朴素轮廓；来信自动保存，不必手动领取 |
| 设置 | 声音、动效、存档 | 导出/导入 JSON；导入与重置会展示将覆盖的进度并确认 |

面板采用单层纸页/底部抽屉。点具体卡片时在同一面板内切详情，返回保留原位置；不叠多层弹窗。操作均可点击完成，拖拽只是以后可能的增强。

### 首次体验脚本

1. 打开直接进入屋里，疙宝正发呆。一句引导：“给它收拾点吃的，它就要出门转转了。”
2. 轻提示行囊；免费饭默认可选，用具可空。确认后布包收口，引导说明“关掉网页，它也会继续旅行”。
3. 15 秒内走向门口。场景留下空座，允许自由看院坝、小铺和手账；不强迫继续停留。
4. 教学旅程过半，信夹多一角纸，“有张来信”；打开是竹乡插画、两句见闻、一个生活细节。
5. 自动回家，新增纪念物摆上固定陈列位；轻提示“回来了，还带了个小东西”。点开内容或直接准备下一趟。

### 可用性及边界

- 点击目标至少 44×44 CSS px；主角画得小，可扩大透明点击区；正文建议 16px，标签最低 14px。
- 首次提示后保留常驻文字入口，不能只靠玩家发现插画热点；键盘焦点、Escape 返回、清楚的按钮名称一并设计。
- 未读采用一个纸角或小点；不跳动、不多处重复冒红点；无网页外推送。
- 出发前改包会重新计等候时间；取消回到在家。出发后物品只读，已选结果不变。
- 刷新恢复位置和旅程；离线回来跨过出发/来信/归来时按顺序一次性补全，不连续弹三层提示。
- 存档失败明确提示“这次进度暂未保存”，保留当前会话并提供导出；不得显示虚假的“保存成功”。
- 标准中文负责操作，四川口语负责生活描述；语义不清时补普通话解释，不堆谐音字。默认名字“疙宝”，首版暂不加取名流程。

## 4. 场景与美术任务

### 家园两景

家设在川西林盘院角的矮檐木屋：竹林、水渠、田地围合住宅是事实参考 [S2]；具体院落与角色生活是原创。采用平原/缓丘景色，不把所有窗景画成高山层叠梯田。

| 场景 | 构图/氛围 | 热点与用途 | 状态差异 |
|---|---|---|---|
| `home` 屋里 | 约 20–30°轻俯视，后墙木窗，左后竹榻，中前矮桌，右侧出入口；柔和散射光 | 疙宝、行囊、固定纪念物陈列位；行囊同时有底部按钮 | 在家有动作；备妥有包；离家空位；归来显示最近一件纪念物 |
| `yard` 院坝 | 左侧屋檐，中前青石地/三处簸箕，右后门边小铺货架，远处竹林与水渠 | 簸箕收成、货架小铺、信夹来信；“屋里”导航回家 | 收成空/部分/满，信夹空/有信；疙宝仅在过门瞬间出现 |

固定陈列位每次显示最近获得的一件，点击进手账；P0 不做摆放编辑器。小铺是商品面板，不新增第三张地图，也不新增商人角色。

### 三地、九张见闻卡

旅行地点以卡片表现，不做可探索地图。每张卡结构为“原创插画 + 标题 + 1–2 句见闻 + 可展开的生活小注”。以下标题、事件、纪念物均为创作提案。

| 目的地 ID / 文化参照 | 三张卡与事件 | 两件纪念物 | 如何体现四川生活 |
|---|---|---|---|
| `route_daoming` 道明竹乡 [S3] | `card_daoming_01`《竹影里打个盹》；`card_daoming_02`《帮忙理了几根竹篾》；`card_daoming_03`《竹篱边吃叶儿粑》 | `souvenir_bamboo_mat` 小竹垫、`souvenir_bamboo_basket` 小竹篮 | 学会用竹编器物装东西、乘凉；不表现“一看就学会复杂非遗技法” |
| `route_chengdu_tea` 成都坝坝茶 [S4] | `card_tea_01`《一碗茶，坐半晌》；`card_tea_02`《听隔壁摆龙门阵》；`card_tea_03`《竹椅底下乘个凉》 | `souvenir_gaiwan` 小盖碗、`souvenir_tea_stool` 小竹凳 | 盖碗、竹椅、闲坐和闲聊进入角色行为；未出镜的人声只写在见闻里 |
| `route_huanglongxi` 黄龙溪河街 [S5] | `card_river_01`《檐下等雨停》；`card_river_02`《沿着河街慢慢走》；`card_river_03`《桥洞里听水声》 | `souvenir_river_sketch` 河街速写、`souvenir_pebble` 圆石小摆件 | 临河街巷、瓦檐与石板路；雨中慢下来；纪念物为虚构旅途所得，不标“当地非遗” |

第三张分别采用竹篱近景、竹椅下低视角、桥洞框景；在同站内区分构图和动作。新增范围为 3 幅原创卡图、3 组见闻及小注文案，不额外增加角色或旅行地图。吃食在故事中也可从旅途获得，不把特定卡绑定为付费吃食专属。

第一张卡文案样例：“竹影子晃来晃去，它坐着坐着就眯着了。醒来包还在，太阳挪了半截。”；茶馆样例：“茶都续了两回，隔壁的龙门阵还没摆完。”

叶儿粑借用真实地方饮食 [S6]，具体叶材和做法随地区不同，不把单一做法写成全川标准。小竹筒、油纸伞、靛蓝布包是本作器物设计；不把通用器物包装为四川独有文化。辣椒结只占一个小色点。

首版不承载节庆日历。川剧、火龙灯舞、彝族/藏族/羌族文化等，后续按具体地区与场合独立研究，避免合成一套泛四川装扮。

### 现有角色素材的生产判断

- 六张 IP 板已经生成，可供轮廓、神态、色彩和动作方向参考，当前尚无用户最终验收记录。
- 已检查的比例板中，“六等分”网格超出头顶和脚底，实际角色没有占满六格；数值标注也不能视为对像素图的测量结果。
- `W≈1.18H` 等是拟定造型目标，需在同基线的最终模型上重新量定。疙瘩分布、指趾和布包背法也要跨姿势核对。
- 游戏素材化时先做 1 张干净角色母版 + 1 张场景色稿，在约 72–96px 角色显示高度验证脸部与剪影，再派生动作。
- 图中文字、界面标签由网页字体渲染；生图只提供美术。概念分析板不可直接当透明精灵图或精确工程规范。

### 画面、动效与声音

- 以《旅行青蛙》的轻俯视、环境主导、手绘轮廓、柔和色块和克制留白为风格参照；原作美术仅作观察资料。
- 每幅画面保留 2–3 个可读的四川生活线索。降低高密度疙瘩和全屏厚纸纹，让角色在小尺寸仍清楚。
- 角色在主场景常态高度约占可见场景高度 12–16%；非全屏大头；场景使用独立前/中/后层遮挡。
- 初始竖屏基准 390×844 CSS px，窄屏检查到 360px；顶部/底部控件独立排版，不随插画一起缩成小字。
- 点按 160ms、抽屉 360ms、场景淡换 240ms；缓动 `cubic-bezier(.22,.61,.36,1)`；单次待机呼吸周期约 4 秒，自发动作间隔 12–25 秒。
- 大幅压缩 ≤12%、伸展 ≤10%只作为跳跃上限；日常呼吸缩放 ≤1.5%。减少动效模式改为静态状态切换。
- P0 固定柔和白昼；旅途卡可有局部雨景，不接真实天气。环境声为竹叶、水渠，反馈声为纸张、布包、收成；首次手动开启声音后播放并记住选择，默认安静。

## 5. 制作清单与技术边界

### 首版资产预算

| 类别 | 数量与复用规则 |
|---|---|
| 角色 | 1 套最终母版；发呆、收拾、吃东西、打瞌睡、走向门口 5 个动作；短跳仅作以后扩展 |
| 家园 | 2 张基础场景，前/中/后层；包、信夹、簸箕、陈列位独立，不为每状态重画整景 |
| 旅行 | 3 地×3 张 = 9 张卡片原画；每张有独立事件文案 |
| 物品 | 3 吃食 + 2 用具 + 6 纪念物 = 11 个图标；纪念物陈列可复用图标 |
| 界面 | 按钮、底部导航、纸页面板、物品槽、商品格、提示条、未读角标 7 类复用部件 |
| 声音 | 可选 1 条轻环境底声 + 3 类反馈音；优先保证静音也能理解 |

### 实现建议（尚未安装或实现）

- Vite + React + TypeScript，CSS 管布局与轻动效；角色/背景以图片分层，暂不引入物理或重型游戏引擎。
- 规则层采用纯函数、配置表与时间戳，UI 不自行结算；`advanceGame(state, now)` 统一推进。
- `GameState` 最少记录版本、主角阶段、盘缠/库存/预留、行囊、当前旅程、已结算旅程 ID、卡片与纪念物、收成时间、偏好、最后有效时间。
- `Trip` 含 `id / departAt / letterAt / returnAt / routeId / cardId / souvenirId / seed`，确认准备时排定出发，真正出发时确定其余结果并持久化。
- 单一本地存档使用 `localStorage`；一个状态快照提交物品与奖励变化，结算用 trip ID 去重；保留上一份有效快照供恢复。
- 同一来源多标签页只允许一个写入者；可用浏览器锁保护读改写，能力缺失时第二页只读并提示回到原页，避免重复奖励。
- 客户端时间回拨不倒扣进度，推进时间取 `max(now, lastSeenAt)`；改钟前跳不做反作弊，但一趟最多结算一次。
- 导入校验版本和字段后再替换；提供导出备份。首版不跨设备同步；素材运行时来自打包内容，游戏运行时不调用生图或大模型 API。
- 首屏只加载家园和角色，卡片按需加载；本地存档不等于离线安装，P0 不承诺无网络首次打开或 PWA 能力。

| 0 前期基线（已完成） | 本方案、四份维护文档、九卡范围 | 目标、口吻、数量与待验证项可追溯 |

| 7 试玩与修正 | 恢复等边界验证、5 人体验与隔日回访、调参 | 按以下标准修正问题，再交付首版 |

详细任务见 [开发顺序](开发顺序.MD)。第 3 步稳定尺寸和模板后，第 4、5 步可同时推进，第 6 步依赖两者完成；每步结束更新四份维护文档。本轮只制定顺序，尚未执行第 1 步。

验收目标是待验证假设，不是已经得到的测试结果：

- 理解：5 人中至少 4 人无需口头说明完成首次准备，并知道角色会自行出发。
- 地方感：隐藏标题后，至少 4 人能指出两项具体四川/成都平原生活线索，并说出画面中的角色在做什么。
- 情绪：隔日询问“记住了哪个动作/哪张信、回来是否出于期待”，收集原话；不以在线时长或签到率替代。
- 交互：最小 360px 宽无截断，热点可点击，关闭任意面板可回场景，静音/减少动效可完成全程。
- 规则：取消不损耗、确认不双扣、归来不双领；第一趟收信先于归来；零盘缠仍可继续。
- 收藏：三站各三张，共九张不同卡；九张全部可获得，集齐第九张才显示全册完成；卡片与六种纪念物分别计数。
- 恢复：刷新、关闭后跨阶段再开、多标签页、存档不可写、旧版本导入均有明确结果；不因后台计时暂停卡住旅程。

主要风险及应对：角色在手机上过细→先做小尺寸母版；真实等待难评审→独立测试时钟；内容少重复快→未见优先并明确样片范围；地方元素只剩装饰→每站必须有行为与见闻；收成造成打卡压力→足量暂存、免费饭、无损失。

范围调整记录遵循“原因 → 用户价值 → 新增资产/界面/规则 → 替换项或阶段 → 更新本文和四份文档”。方向与数量是基线，时长/价格/权重可经试玩调整；变动必须留在交接中。
